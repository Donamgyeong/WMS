# 근로시간 계산 엔진

2026-11-13 · 로컬 AGENTS.md·기존 계획·근태 기록 결정 기준. Notion 원문 정책을 새로 결정하거나 변경하지 않는다.

## 계산 계약

`engine.ts`는 DB·Next.js에 의존하지 않는 순수 계산이다. 수락 이벤트, 기준 시각, 날짜별 정책·일정·휴일 및 선택적인 야간 종료 시각을 입력받는다. 시각은 UTC instant로 보존하며 날짜 경계는 기존 기록과 동일한 Asia/Seoul이다. 지원 API 날짜는 2000~2099년이다. 근무일은 출근일로 유지한다.

근무 상태 구간에서 실제 휴게만 제외한다. 기본 휴게 60분 충족 여부는 기록하고 미충족 시 `BREAK_REQUIREMENT_UNMET`을 남긴다. 휴게 60분 자동 차감, 기록 시각 반올림, 자동 퇴근은 하지 않는다. 이벤트는 ID 중복·시각 역전/동일 시각·기준 시각 이후·잘못된 상태 순서를 거부한다. 열린 세션은 명시한 기준 시각까지 잠정 계산한다. 시간은 밀리초 정밀도로 연산하고 NUMERIC 분 값으로 저장한다.

누적 실근로의 정책 기본 근로시간, 22시, 자정, 명시된 야간 종료 시각으로 분할한다. 일정의 의무 근로시간은 별도로 반환하며, 단축 일정이라는 이유로 연장 기준을 낮추지 않는다. 연장 플래그는 실제 초과시간 분류이고 승인 완료를 뜻하지 않는다. 실제 연장 구간은 `OVERTIME_APPROVAL_UNDECIDED`를 남긴다. 임금 배율·포괄 차감·법정수당 비교는 payroll의 후속 책임이며 `applied_multiplier`는 NULL이다.

야간 종료 시각은 확정되지 않았다. `nightEndHour`는 명시적 계산 옵션(0~22 정수)이며 정책 확정 기록이 아니다. 생략하면 22시 이후는 야간 true, 00~22시는 판정 불가 NULL이다. 0을 지정하면 야간은 자정에 종료하는 시나리오다. 엔진 버전과 옵션을 스냅샷에 보존한다.

반차·승인 휴가의 구체적인 매핑과 반차 초과 연장 인정은 미정이다. 승인 휴가가 걸친 날짜는 보수적으로 반차 관련 사유를 남기고 연장 분류를 보류한다. 내부 `leave_type=HALF_DAY` 단일 기록에는 확정된 의무 실근로 240분을 적용하되 휴게 의무는 NULL로 유지한다. 그 밖의 휴가 유형은 의무시간도 미정으로 남기며 외부 유형 매핑은 구현하지 않는다. 근무 중 정책 변경·누락도 해당 구간의 연장 분류를 NULL로 남긴다. 등록된 직원 캘린더·명시적 일정으로 휴일을 판단하고 주말을 자동 휴일로 취급하지 않는다. 휴일 근거가 없거나 지원하지 않는 시간대의 캘린더라면 해당 분류를 보류한다. 캘린더 적용 기간은 날짜 기준으로 처리한다.

승인 정정의 재생 계약은 아직 없으므로 원본 이벤트를 임의로 수정하지 않고 `CORRECTION_REPLAY_PENDING`을 남긴다. 이 결과를 정정 반영 완료로 사용하면 안 된다. 분류 미정과 실제 시간 계산은 별도로 제공한다.

## 저장·버전

기존 `calculation_version=1`은 출퇴근 수집 세션이다. 수집 세션에 원본 이벤트가 연결되며 기록 API는 이 버전만 조회·갱신한다. 재계산은 종료된 수집 세션에서 새 파생 세션을 만든다. 원본 이벤트 FK는 변경하지 않는다. 열린 세션은 저장 재계산을 409로 거부하고 조회 시 잠정 계산한다.

직원 행 FOR UPDATE 잠금으로 기록·조회·재계산을 직렬화한다. 재계산 범위는 출근일 `[from,to)`이며 하나의 트랜잭션이다. 직원의 최대 버전+1을 새 버전으로 사용하고 같은 요청 내 변경 세션에는 같은 버전을 적용한다. 이벤트·정책·일정·휴일·휴가·정정·엔진·옵션의 fingerprint가 마지막 저장 결과와 같으면 이전 결과를 반환한다. 다른 입력이면 이전 세션·구간을 보존하고 새 버전을 생성한다. 확정 정산·기존 구간은 수정하지 않는다.

스냅샷에 원본 ID와 실제 입력 데이터, 계산 옵션·엔진 버전·계산 결과를 저장한다. 조회는 근무일별 최신 파생 결과를 선택한다. 저장 결과와 조회 옵션이 다르거나 저장 결과가 없으면 원본으로 현재 입력을 계산하며 버전 1로 명시한다. 저장된 결과는 정책 수정만으로 자동 갱신되지 않는다. 관리자가 명시적으로 재계산해야 새 입력이 반영된다.

0006 마이그레이션은 세 분류 플래그에 NULL을 허용하고 구간별 `unresolved_reasons`를 추가한다. 기존 EXCLUDE·원본 불변·세션 근거 보존·정산 보호 트리거는 유지한다.

## API

- `GET /api/worktime?from=2026-11-01&to=2026-12-01&basis=WORK_DATE`
- 선택: `employeeId`(기본 본인), `nightEndHour`, `weekStartsOn`(0=일요일~6=토요일).
- `basis=WORK_DATE`는 출근일 귀속, `ACTUAL_TIME`은 실제 구간을 기간 경계에서 배분한다. 반드시 명시한다.
- `POST /api/admin/worktime/recalculate`: JSON `{ "employeeId": "…", "from": "2026-11-01", "to": "2026-12-01", "nightEndHour": 6 }`. `nightEndHour`는 생략 가능하다. 관리자·허용 Origin·JSON 검사를 한다.

직원은 본인, 부서장은 담당 부서, 관리자는 전체 조회가 가능하다. 재계산은 관리자 전용이다. 비활성·초기 비밀번호 변경 미완료 계정은 기존 인증 정책을 따른다. 임금 정보는 반환하지 않으며 모든 응답은 no-store다. 기간은 시작일 포함·종료일 제외, 최대 366일이다. 잘못된 날짜·중복/알 수 없는 파라미터는 400이다.

일별·주별·월별 집계에 선택된 세션과 버전·미확정 사유를 제공한다. 최신 버전만 합산하고 실제 시간은 포괄 포함시간과 무관하게 보존한다. 분류별 합계는 NULL을 유지한다. 연장·야간·휴일은 서로 중첩되므로 합산해 총근로로 사용하지 않는다.

주 시작일을 생략하면 weekly=NULL, `WEEK_START_UNDECIDED`를 반환한다. 지정하면 주별 3120분 초과 여부를 계산하며, 경보 정책은 UNDECIDED다. 요청 기간에 잘린 주는 partial=true이며 start/end로 실제 집계 범위를 표시한다. 월별 결과도 요청 기간으로 잘라 start/end를 제공한다. 부분 주에서 52시간 이하라는 결과는 전체 주가 52시간 이하라는 보장이 아니다. `exceeds52Hours`는 공통 집계 결과의 단순 3120분 초과 비교이며 주간 관리에는 weekly 결과만 사용한다.

## 검증

단위 테스트: 실근로·다중 휴게·8시간·22시·자정·월말/연말·밀리초·미정 분류·이벤트 검증·집계 귀속·버전 선택·52시간 경계.

DB 통합 테스트: 재계산 저장·동시 실행 멱등성·입력 변경·원본/근거 보존·구간 중복·열린 세션 롤백·권한·API 입력/Origin·임금 필드 비노출.

E2E: 실제 로그인·출근·잠정 조회·퇴근·관리자 재계산·동일 요청 재실행·직원 최신 결과 조회·기존 기록 UI 보존. 기존 인증·GPS·출퇴근 테스트도 회귀 실행한다.

정정 승인/재생, 휴가 유형별 계산, 최종 임금·정산 확정, 운영 배치·자동 재계산, 대시보드의 예시 주간 차트 교체는 후속 범위다.
