# DB 물리 스키마

2026-11-13 · Notion 근무정책·시스템 설계·ERD v1.2 재확인. 업무 API와 계산 엔진은 별도 구현 대상이다.

`src/db/schema/index.ts`가 스키마 진입점이다. ERD 23개 테이블과 기존 Better Auth 테이블 및 담당 부서 매핑을 유지한다. 영역별로 identity, policy, calendar, attendance, payroll 파일을 사용한다. 금액·분 단위 값은 반올림 정책을 확정하지 않도록 자릿수 제한 없는 NUMERIC으로 저장한다. 좌표만 소수점 7자리를 사용한다.

## 기간·버전·관계

- 날짜 적용 기간과 정산 기간은 `[시작, 종료)`다. effective_to NULL은 무기한이며, 맞닿은 기간은 허용한다.
- GiST EXCLUDE와 btree_gist로 같은 직원의 시급·계약·정책 배정 중복을 차단한다. 정책은 같은 이름의 적용 기간 중복을 금지한다. 직원 캘린더는 동일 캘린더의 배정 중복을 막고 여러 캘린더 동시 배정을 허용한다.
- 세션은 직원·근무일·계산 버전으로 고유하다. 구간은 직원·계산 버전별로 시간 중복을 금지한다. 재계산은 해당 직원의 관련 기간에 일관된 새 버전을 사용한다. 다른 버전은 동일 시각을 보존할 수 있다. 조회 서비스는 선택한 버전만 집계해야 한다.
- 구간의 직원·버전·시간 경계는 세션과 일치해야 한다. 근로 구간 생성 후 세션의 계산 근거 변경은 새 버전으로 처리한다. 세션에는 원본 이벤트·정정 ID와 정책 버전을 포함하는 input_snapshot을 작성해야 한다.
- 이벤트·정정의 직원과 참조 세션·원본 이벤트의 직원은 복합 FK로 일치시킨다. 이벤트는 직원·request_id로 멱등성을 보장한다. 요청 ID 생성·재사용 계약은 근태 API에서 구현한다.
- 직원의 active가 기존 인증 상태의 기준이다. 직원 이름은 auth_users.name이 인증 표시 이름이다. employees의 employee_no/name/hired_at/terminated_at은 인사정보 보완용 선택 필드로 추가했다. 실제 사번·입사일을 추정해 채우지 않는다. 정식 인사 등록 서비스에서 필수 입력과 backfill을 구현할 때 NOT NULL 전환을 검토한다.
- departments.manager_id는 대표 부서장, managed_departments는 실제 접근 범위다. 권한은 기존 역할·담당 부서 서버 검사로 판정한다. 대표 부서장 필드만으로 접근 권한을 부여하지 않는다.
- 이력 삭제는 기본 NO ACTION FK로 차단한다. 일반·야간·휴일 플래그는 독립적이며 휴일 배율은 NULL을 허용한다. 토·일 여부로 휴일을 자동 생성하지 않는다.

## 원본·정산 보존

attendance_events, payroll.audit_logs, payroll.payroll_adjustments는 UPDATE/DELETE 트리거로 변경을 금지한다. 이벤트의 선택 work_session_id도 삽입 시에만 설정한다. 이후 재계산 연결은 세션 input_snapshot에 원본 ID를 저장한다. 파생 세션을 먼저 만들거나 이벤트를 세션 없이 기록할 수 있다.

정산은 기간·직원·계산 버전으로 고유하다. 계약의 포괄 포함시간 기본값은 960, allocation_policy와 allowance_comparison_policy는 UNDECIDED다. 미정 계약은 UNRESOLVED 계산만 허용하고 추가 지급액·총액은 NULL로 유지한다. 포함 시간과 실제 연장시간은 별도로 저장한다. 야간 연장은 전체 연장시간의 부분집합이다. 정책 상세는 향후 승인된 설정값을 사용하며, 지금 배정 순서를 구현하지 않는다.

확정 전 서비스는 input_snapshot/basis_snapshot에 실제 정책·시급·계약·구간 및 계산 근거를 채우고 unresolved_reasons를 작성해야 한다. DB는 미정 계약, 미정 금액·라인아이템, 미확정 계산이 있는 기간의 확정을 차단한다. JSON 스냅샷의 업무 의미와 총합 대조, 전체 미정 정책 해소 여부는 후속 정산 서비스에서 추가 검증해야 한다. 스키마만으로 임금 계산의 적법성이나 정확성이 보장되지는 않는다.

FINALIZED 계산·라인·기간은 변경할 수 없다. 라인에서 참조하는 근로 구간은 확정 전부터 변경·삭제를 금지한다. 정정 재계산은 새 구간·계산 버전을 만들고, 이미 확정된 기간의 사후 변경은 append-only 조정 이력으로 보존한다. 기간 상태 변경과 라인 변경은 부모 행 잠금으로 직렬화한다.

## 접근과 마이그레이션

시급·계약·정산·감사 테이블은 payroll 스키마에 있고 PUBLIC 권한을 제거한다. DB 소유자는 접근할 수 있으므로 이것만으로 사용자별 권한이 보장되지는 않는다. 업무 임금 API를 만들 때 기존 관리자 서버 권한 검사와 최소 응답 필터를 반드시 적용한다. 이번 작업은 임금 API를 추가하지 않는다.

0000·0001 기존 마이그레이션을 보존한다. 0002는 ERD 테이블, 0003은 범위·보존 트리거 및 인덱스, 0004는 NUMERIC 정밀도 제한 제거, 0005는 확정·세션 무결성 보강이다. Drizzle이 표현하지 않는 EXCLUDE·트리거·일부 CHECK·인덱스는 custom SQL에서 관리한다. 후속 생성 SQL에서 수동 제약이 손실되지 않는지 검토한다. btree_gist 설치 권한이 있는 DB 운영 계정으로 마이그레이션한다.

검증은 전용 `_test` DB에서 전체 마이그레이션 후 `npm run test:integration`을 실행한다. 스키마 테스트는 각 테스트를 트랜잭션으로 격리하고 롤백한다. 기존 인증 테스트의 TRUNCATE CASCADE는 업무 테이블도 초기화하므로 개발·운영 DB에서 실행하지 않는다.
