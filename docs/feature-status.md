# 화면별 실제 데이터 연결 및 미구현 기능

확인일: 2026-11-13 (Asia/Seoul). 현재 코드 기준이며 근무정책을 변경하거나 미정 정책을 확정한 문서는 아니다.

모든 관리 화면에서 예시 데이터와 작동하지 않는 예시 저장 버튼을 제거했다. 데이터가 없으면 빈 상태를 표시한다. 하위 관리 화면은 수동 기간 조회·재조회, 직원 선택 및 이름·내용 검색을 제공한다. 부서 필터는 직원과 연결된 행에 적용하며 공통 설정·정산 기간 등 공통 행은 유지한다. 표는 30행씩 페이지를 나눈다.

하위 관리 API: `GET /api/{team|admin}/management/{화면 key}`. `from` 포함, `to` 제외, 최대 366일. 선택 조건은 `employeeId`, `workDate`, `calculationId`다. 직원별 시급·계약 이력과 공통 정책은 전체 이력을 표시하며, 날짜 범위는 근태·일정·정산 기간에 적용한다.

부서장은 담당 부서만 조회한다. ADMIN 겸직이어도 `/team` 범위를 넓히지 않는다. 관리자 데이터는 관리자 API에서만 반환하고 비관리자에게 시급·계약·정산·임금 스냅샷을 제공하지 않는다. 근태 원본 조회에는 검증 결과를 표시하고 GPS·IP 검증 증거 원문은 전달하지 않는다.

## 미구현 — 외부 연동

- 다우오피스 휴가·반차 신청/승인 동기화. 현재 `leave_records`에 저장된 기록만 조회한다.
- 공휴일·대체공휴일 데이터 자동 수집·갱신. 현재 저장된 휴일만 조회한다.

## 정책 결정 후 구현할 항목

- 월 960분 포괄 포함시간의 일반·야간 배정 순서 및 고정수당과 실제 법정수당 비교 방식.
- 반차 휴게시간 및 4시간 초과분 연장 인정, 연장·정정 승인 절차.
- 휴일근로 배율·포괄 포함 여부, 주간 시작 요일·경보 기준, 야간 종료 시각, 반올림·세금·공제 범위.

미확정 값은 `NULL`/미확정으로 유지한다. 시급·계약 입력만으로 정산을 확정하지 않으며, 정산 금액이 없다는 이유로 0원으로 표시하지 않는다. 정책 결정과 서비스 구현은 별도 작업이다.

## 조직·계정·정책·근무지 관리 구현 (2026-11-13)

`/admin/organization`과 `/admin/settings`의 관리 데이터 편집에서 등록·변경한다. `GET/POST /api/admin/configuration`은 관리자 전용이며 POST는 로그인·초기 비밀번호 변경 완료·신뢰 출처·JSON을 검사한다. 조회 revision을 변경 요청에 포함하며 다른 변경이 있으면 409로 거부한다. 편집 데이터 새로고침 후 대상을 다시 선택한다.

- 부서 계층 순환, 이메일·사번 중복, 잘못된 입퇴사일, 부서장 담당 범위 불일치를 차단한다. 지정 부서장은 해당 부서 담당 권한이 있는 활성 MANAGER만 가능하다. 담당 권한 해제·비활성화 시 지정도 해제한다.
- 마지막 활성 관리자 비활성화·권한 제거를 차단한다. 직원 편집·계정 상태·비밀번호 초기화는 기존 세션을 폐기한다. 초기 비밀번호는 12~128자이며 다음 로그인에서 변경해야 한다. 이메일 변경·영구 삭제·과거 소속 이력은 제공하지 않는다.
- 근무지는 좌표·IPv4/IPv6 CIDR을 함께 저장한다. 반경은 100m로 고정하고 과거 검증 증거는 보존한다. CIDR은 네트워크 주소를 입력해야 하며 호스트 비트·정규화 후 중복도 DB에서 차단한다.
- 정책 값은 확정 근무 규칙으로 생성하며 미정 항목은 NULL/미정으로 보존한다. 내일 이후 시작일만 지원한다. 같은 이름의 새 버전은 이전 정책·걸친 배정을 해당 일자에 종료하고 동일 직원의 새 배정을 이어 만든다. 새 정책 종료일이 기존 배정 범위를 수용하지 못하거나 예약 배정과 충돌하면 전체 변경을 거부한다.
- 개별 배정 전환은 기존 배정을 시작일에 종료하고 새 배정을 저장한다. 종료일 이후 이전 정책을 자동 복원하지 않는다. 저장 원본·열린 세션·과거 계산·정산 스냅샷을 재작성하지 않는다.
- CLI도 동일 서비스를 사용한다. DB 운영자 CLI는 웹 인증 대신 로컬 DB 접속 권한으로 실행되지만 마지막 관리자·기간·근무 규칙 검증은 동일하다. `attendance-setup assign`도 내일 이후만 지원한다.

스키마 변경은 없다. 관리 변경은 테이블 잠금으로 직렬화한다. 대규모 조직에서의 잠금 범위 최적화, 상세 변경 감사 이력은 후속 범위다.
