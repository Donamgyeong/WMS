# 근태 관리 시스템 구현 계획

작성일: 2026-11-12 (Asia/Seoul) · 상태: 인증 기본 흐름 구현, 근태·임금 업무 기능 구현 미착수

## 근거 및 현재 상태

Notion의 [근로 → 근태 관리 시스템](https://app.notion.com/p/41623542cf8c803abb1acea06a366296)과 하위 [근무정책](https://app.notion.com/p/41623542cf8c8169a41bd9cc3b48c3fb), [시스템 설계](https://app.notion.com/p/41623542cf8c8103bcf9f6887e09ecb0), [ERD v1.2](https://app.notion.com/p/41623542cf8c81a3bf3be8375a9f754a)를 읽고 작성했다. 근로의 다른 형제 문서는 이번 범위에 포함하지 않는다.

개발 스택은 Next.js App Router + TypeScript, PostgreSQL, Drizzle ORM(node-postgres)으로 확정했다. Docker Compose로 Node.js 24 앱과 PostgreSQL 17을 실행한다. 개발 환경 실행·마이그레이션 절차는 루트 `README.md`를 따른다. 아래 단계는 제안이며 일정·담당자·인증·운영 배포 방식은 확정되지 않았다. 근무 규칙과 계산 시 지켜야 할 제약은 루트 `AGENTS.md`를 따른다.

## 구조 설계 현황

2026-11-13: [전체 구조 설계](architecture.md)에 모듈 책임, 의존 방향, 데이터 흐름, 권한 및 검증 계획을 정리했다. `src/modules`, `src/components`, `src/shared`, `tests`의 기본 디렉터리와 DB 스키마 진입점을 구성했다. 인증·배포 방식, 상세 API 계약 및 물리 스키마는 후속 설계 대상이며, 1단계 전체가 완료된 것은 아니다.

## 목표와 범위

검증된 출퇴근·휴게 원본 이벤트를 바탕으로 실근로시간을 계산하고 직원·부서장에게 제공한다. 임금 계산·정산·Excel은 관리자 전용 경로로 제공한다.

| 역할 | 제공 기능 및 권한 |
| --- | --- |
| 직원 | 본인 출퇴근·휴게, 일·주·월 근로시간, 오늘 현황·예상 퇴근·캘린더 |
| 부서장 | 부서원 실근로시간, 주간 막대그래프, 52시간 위험 인원, 누락·팀 통계. 임금 접근 불가 |
| 관리자 | 조직·권한·근무지·정책·근태·휴일 관리, 시급·계약·임금 계산, 정산·Excel |

P0는 원본 이벤트 기록, 근로시간 계산, 세 역할의 기능, 임금 엔진·보고서, 조직·근무지·휴일·개인 일정 관리까지 포함한다. P1은 다우오피스 휴가·반차 동기화, 근태 정정 승인, 위험·누락 알림, 확정 정산 조정 및 관리자 접근·Excel 감사 로그다. 미정 정책 때문에 확정할 수 없는 금액은 미확정 상태로 제공한다.

## 처리 구조

출퇴근·휴게 요청 → PC IP/모바일 GPS 검증 → 원본 이벤트 저장 → 세션·근로 구간 계산 → 실근로시간 집계·대시보드 → 별도 관리자 임금 계산 → 정산·Excel.

- 원본 이벤트와 파생 세션·구간을 분리해 정책 변경·정정 후 재계산 가능하게 한다.
- 일반 근태와 관리자 임금 API를 분리하고 서버에서 본인·부서·관리자 범위를 검사한다.
- 임금·계약·시급은 `payroll` 스키마로 격리한다. UI 비노출만으로 접근 통제를 대신하지 않는다.
- 정책·시급·계약의 유효 기간과 계산 버전, 확정 정산 스냅샷을 보존한다.

## 데이터 모델 계획

ERD v1.2의 다음 테이블을 물리 설계의 기준으로 사용한다.

| 영역 | 테이블 |
| --- | --- |
| 조직·정책·근무지 | departments, employees, employee_roles, work_policies, employee_policy_assignments, workplaces, workplace_ip_ranges |
| 근태·휴가 | attendance_events, work_sessions, work_segments, attendance_corrections, leave_records |
| 휴일·일정 | holiday_calendars, holidays, employee_calendar_assignments, work_schedules |
| 시급·계약·정산 | hourly_rate_histories, compensation_contracts, payroll_periods, payroll_calculations, payroll_line_items, payroll_adjustments, audit_logs |

- 직원→세션→구간, 세션→이벤트, 정산→라인아이템→원본 구간의 추적 관계를 유지한다.
- 이벤트에는 발생·기록 시각, 출처, 근무지, 검증 상태를 보존한다. 세션에는 의무·실제 근로 분과 계산 버전을 둔다.
- 구간에는 연장·야간·휴일 플래그를 독립 저장하고 시작 < 종료 및 중복 금지를 보장한다.
- PostgreSQL의 daterange/tstzrange 및 GiST EXCLUDE를 기간 중복 방지 수단으로 검토한다. DB는 PostgreSQL로 확정했다.
- 시급은 NUMERIC, 임금 결과는 근거·적용 시급·배율·버전과 함께 관리한다. 금액 반올림 규칙은 별도 결정한다.
- 계약 기본 포함시간은 960분, allocation_policy는 UNDECIDED로 시작한다. 미확정 추가 지급 분·금액은 NULL을 허용한다.
- 정산 기간 상태는 OPEN/CALCULATED/FINALIZED를 기준으로 하되 미정 정책과 필수 입력 누락 시 확정 차단 조건을 설계한다.
- 인덱스·정산 버전 고유성·적용 기간 경계·삭제 정책은 물리 설계에서 구체화한다.

## 검증 시나리오

1. 기본 8시간 실근로와 휴게 1시간을 분리하고 출근 시각에 따른 예상 퇴근을 검증한다.
2. 휴게가 여러 번이거나 퇴근·휴게 종료가 누락된 경우 정상 기록과 구분한다. 중복 요청이 시간 집계를 늘리지 않는지 확인한다.
3. 8시간·22:00·자정·주/월 경계와 시급·정책·계약 변경 경계에서 구간·집계·버전이 일관되는지 검증한다.
4. 월 실제 연장 20시간일 때 실근로는 그대로 유지하고 포함 16시간·추가 대상 4시간을 분리한다. 배정 미정 시 추가 지급액과 총액은 미확정이어야 한다.
5. 주 실제 근로 52시간 전후, 회사 휴일·대체공휴일·개인 휴무일을 구분해 검증한다. 토·일을 일괄 휴일 처리하지 않는다.
6. 직원의 타인 조회, 부서장의 타부서·임금 조회, 비관리자의 임금 API·Excel 접근을 차단한다.
7. 동일 원본·정책·버전의 재계산 결과가 같고 확정 정산이 이후 정책 변경으로 덮어써지지 않는지 확인한다.
8. 관리자 보고서·Excel 요약과 상세 구간의 합계·미확정 표시가 일치하는지 확인한다.

## 착수 순서

먼저 1단계의 기술·권한·정책 결정 기록을 작성한 뒤 2~4단계의 데이터·원본 이벤트·실근로 계산을 구축한다. 그 결과를 바탕으로 대시보드와 관리자 임금 기능을 진행한다. 미정 정책에 의존하는 최종 금액 확정은 결정 이후에 진행한다. 현재 산출물은 계획·근무 규칙 문서와 Next.js/Drizzle/Docker Compose 개발 환경이다. 업무 기능·전체 ERD 물리 스키마·외부 연동은 후속 구현 대상이다.

## 인증 구현 현황 (2026-11-13)

[인증 결정 기록](decisions/0001-authentication.md)에 따라 Better Auth·이메일/비밀번호·DB 세션·계정 발급/비활성화 CLI·역할 및 담당 부서 범위 판정·초기 비밀번호 변경을 구현했다. 스키마 마이그레이션과 단위/DB 통합/E2E 테스트를 추가했다. 관리자와 부서장 화면은 권한 확인용이다. SSO, 계정 관리 UI, 전체 조직 이력, 근태 및 임금 기능은 후속 대상이며 1·2단계 전체가 완료된 것은 아니다.
