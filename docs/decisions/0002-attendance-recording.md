# 출퇴근·휴게 기록

2026-11-13 · 사용자 채팅 결정과 로컬 근무 규칙에 따른 첫 구현. Notion 원문 변경·재확인 결과는 아니다.

## 적용 기준

- 시간 저장은 timestamptz, 근무일·화면 시각은 Asia/Seoul을 사용한다.
- 자정을 넘긴 연속 근무의 work_date는 출근일이다. 휴게·퇴근은 열린 세션을 이어간다. 실제 시각은 이동하지 않으며 주·월 정산이나 휴일 경계의 판정을 이 결정으로 대신하지 않는다.
- PC IP와 PC·모바일 구분은 사용자 결정에 따라 요청 헤더를 신뢰한다. 직원 신원은 로그인 세션에서만 얻는다.
- 기기는 `x-attendance-device: PC|MOBILE` 우선, 없으면 `Sec-CH-UA-Mobile: ?1` 또는 모바일 User-Agent로 판별한다. UI는 GPS 요청과 일치하는 명시적 헤더를 보낸다. 잘못된 명시적 값은 400이다.
- PC IP는 X-Forwarded-For 첫 항목, 헤더가 없으면 X-Real-IP를 사용한다. 유효한 IPv4·IPv6가 아니면 400이다. PostgreSQL inet/CIDR 포함 검사로 허용 IP를 검증한다.
- 모바일은 근무지 좌표와 Haversine 거리 100m 이하를 허용한다. 정확도 값은 원본에 보존하되 별도 정확도 임계값·반경 가산은 적용하지 않는다. 위치 누락·잘못된 좌표는 400, 거리 초과는 403이다. 기존 근무지별 반경 값과 무관하게 이번 결정인 100m를 적용하며 등록 CLI도 100m를 저장한다.
- 브라우저 GPS는 보안 컨텍스트(HTTPS 또는 localhost)가 필요하다.

## API

| 경로 | 요청 | 결과 |
| --- | --- | --- |
| GET /api/attendance/status | 로그인 쿠키 | 본인 현재/당일 세션·수락 이벤트·실근로/휴게 분·근무지 목록·서버 시각 |
| POST /api/attendance/events | 로그인 쿠키, 허용 Origin, application/json | 이벤트 ID와 replayed; 최초 201, 동일 재시도 200 |

POST 본문은 `eventType`, `requestId`, `workplaceId`, 선택적 `location: { latitude, longitude, accuracy }`만 허용한다. 직원 ID나 시각 주입은 400이다. 종류는 CLOCK_IN/CLOCK_OUT/BREAK_START/BREAK_END다. requestId는 8~100자의 영숫자·밑줄·하이픈이다. 클라이언트는 UUID를 발급한다.

출근 전→출근→근무 중→휴게 시작→휴게 중→휴게 종료→근무 중→퇴근 순서다. 휴게를 여러 번 기록할 수 있다. 휴게 중 퇴근은 409로 휴게 종료를 안내한다. 동일 근무일에 퇴근 후 재출근은 이번 버전에서 409이며, 이전 출근일의 야간근무를 종료한 뒤 오늘 새 출근은 허용한다. 근무시간대 밖이라는 이유로 실제 기록을 거절하거나 기본 휴게 60분을 자동 차감하지 않는다.

모든 응답은 no-store다. 인증은 기존 비활성 계정·초기 비밀번호 변경 차단을 따른다. 상태 조회는 직원 행 공유 잠금으로 기록 트랜잭션 중간 상태를 읽지 않는다. 타인 ID 필터와 임금 필드는 제공하지 않는다.

## 동시성·보존

기록은 직원 행 FOR UPDATE 잠금 후 멱등성·검증·상태 확인·세션 및 이벤트 저장을 하나의 Drizzle 트랜잭션으로 처리한다. 서버 시각을 사용하며 동일 직원의 연속 이벤트는 최소 1ms 증가시켜 순서를 보장한다. 이벤트는 기존 DB 트리거로 수정·삭제를 금지한다.

동일 직원·requestId의 정규화 본문과 기기가 같으면 기존 결과를 반환한다. 다른 내용은 409다. 근무지 검증에 실패한 유효 요청은 REJECTED 이벤트로 커밋한 뒤 403을 반환한다. 거부된 요청 ID는 성공 요청으로 재사용하지 않으며, 위치를 새로 확인한 재시도는 새 ID를 쓴다. 잘못된 입력·정책 누락·상태 오류는 이벤트를 만들지 않는다.

응답 유실·5xx 시 UI는 동일 본문·요청 ID로 다시 시도한다. 진행 중에는 버튼과 근무지 변경을 잠근다. 재시도 정보는 해당 페이지 메모리에 유지한다. 새로고침 시 서버 상태를 다시 읽는다.

## 파생 계산과 범위

수락 이벤트로 현재 상태와 실제 경과 시간을 재생한다. 실제 휴게 구간만 제외하고 열린 휴게는 조회 시각까지 휴게로 계산한다. 분 값은 초·밀리초를 버리지 않으며 UI에서만 완료된 분으로 표시한다. 30초마다 조회를 갱신한다.

세션은 입력 이벤트 ID·정책 ID/버전·엔진 버전을 스냅샷에 보존한다. 열린 세션의 저장된 분은 마지막 기록 시점 기준이며 조회는 현재 시점까지 다시 계산한다. 퇴근 시 실제 시간·휴게 합계를 저장한다. 미정 분류를 확정하지 않도록 종료 세션은 UNRESOLVED로 둔다. 원본에서 같은 시간을 재생할 수 있다.

이번 구현은 근로 구간의 연장·야간·휴일 분류와 work_segments 생성, 반차 의무시간 판정, 주·월 집계, 정정 승인, 임금·정산을 포함하지 않는다. 기본 정책의 의무시간은 참고 입력이며 반차 판정 결과가 아니다. 이전 날짜의 열린 세션에는 확인 안내를 표시하며 자동 퇴근·휴게 종료는 하지 않는다. 대시보드의 주간 통계·누락 안내·일정은 예시임을 표시한다.

## 설정과 검증

DB 운영자는 `scripts/attendance-setup.ts`로 근무지·CIDR과 직원 기본 정책을 등록한다. 기존 값·정책 이력을 덮어쓰지 않으며 배정 기간 중복은 DB에서 차단한다. 실제 좌표·네트워크·직원 정보 없이 개발 DB를 임의 구성하지 않는다. 스키마 변경은 없으며 기존 마이그레이션을 사용한다.

단위 테스트는 상태 전이 전체 조합·여러 휴게·자정/월말/연말·소수 분·GPS 거리·헤더 형식을 검증한다. 통합 테스트는 실제 DB/API의 권한·중복·동시 요청·원본 보존·검증 거부·정책 누락 롤백·야간근무 세션 연결·설정 CLI를 검증한다. E2E는 실제 PC 기록·모바일 GPS·응답 유실 후 멱등 재시도와 기존 인증·화면 크기별 레이아웃을 검증한다.
